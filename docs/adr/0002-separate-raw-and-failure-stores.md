# 0002. 원본 로그 저장소와 실패 사례 저장소를 분리한다

- 상태: 채택(브리프 6절·4절, D15).
- 맥락: 원본 Trace에는 개인정보가 있고, 실패 사례·비식별 trace·지표에는 비식별 뒤 데이터만 있어야 한다. 이웃 영역(합성 데이터, model-lab, 문항 저작)은 후자만 읽는다.
- 결정: 저장소 둘(`log.db` 원본, `failures.db` 사례·trace·aux)을 코드와 데이터베이스(계정) 수준에서 나눈다. 원본은 `DeidentifierView`로 비식별 처리기만 읽는다(`tests/test_raw_access.py`가 다른 모듈의 접근을 막는다).
- 왜: 개인정보 경계를 저장소 경계와 일치시키면 "읽기 면에는 비식별 뒤의 데이터만 간다"는 수용 기준(브리프 4절)을 구조로 보장한다. 최소 권한 원칙(저장소별 권한)에 따른다.
- 대안: 한 데이터베이스의 두 표 -> 읽기 면 계정이 원본 표 권한을 가질 수 있는 구성 오류가 가능해 버린다.
- 결과: 얻는 것은 읽기 면의 구조적 격리. 감수하는 것은 한 프로세스(ingest)가 두 접속 정보를 가질 수 있다는 점과 읽기 제한이 DB 권한이 아니라 코드 관례라는 점(점검 C8). `OPS_DB_SCHEMA=verify`로 DDL 권한은 뺄 수 있으나 계정 분리는 deploy 결정이다.
- 되돌리는 조건: 없음에 가깝다(개인정보 경계). 계정 분리를 DB 권한까지 내리는 것은 후속.
