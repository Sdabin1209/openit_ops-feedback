# 0034. 경로별 요청 본문 상한을 노출 선언에 적고 서버 상한과 같게 둔다

- 상태: 채택(계약 3.4.7 `Exposure.routes[].max_body_bytes`, RUNTIME R3.5·R10.13).
- 맥락: 공개 입구와 영역 게이트웨이가 경로별 상한으로 앱에 닿기 전 413을 낸다. 이 서비스는 이미 서버 쪽 상한을 가진다(수집 8 MiB, 검토 게시 1 MiB). 두 값이 어긋나면 한쪽이 먼저 자른다.
- 결정: `deploy-exposure.json`에 `/v1/traces`는 8388608(8 MiB, 수집 봉투 하나), `/v1/cases/*/review`는 1048576(1 MiB, 검토자가 쓰는 짧은 JSON)을 적는다. 읽기 경로(GET)는 본문이 없어 적지 않는다(기본 8 MiB는 쓰이지 않는다). 시험이 선언과 코드 상수(`MAX_BODY`, `MAX_REVIEW_BODY`)의 일치를 본다.
- 왜: 값의 출처는 ADR 0008의 임의 상한(측정 안 함)이다. 표준(RFC 9110 15.5.14)은 413의 의미만 정하고 값은 정하지 않는다. 한 곳(코드 상수)에서 정하고 선언이 같음을 시험으로 지키는 것이 어긋남을 막는다.
- 검토한 대안: 선언을 기본값에 맡김(8 MiB): 검토 경로의 1 MiB와 어긋나 게이트웨이는 통과시키고 서버가 413을 낸다(동작은 같지만 두 값이 다르다). 코드를 선언에서 읽음: 설치된 이미지에 선언 파일이 없다.
- 결과: 얻는 것은 한 값. 감수하는 것: 값은 여전히 측정하지 않았다.
- 되돌리는 조건: 실제 봉투·검토 본문 크기를 측정해 상한을 조정할 때.
