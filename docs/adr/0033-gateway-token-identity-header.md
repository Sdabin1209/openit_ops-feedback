# 0033. 사람 신원 헤더는 게이트웨이 토큰에서만 쓴다

- 상태: 채택(계약 3.4.5 CONVENTIONS 6절 "게이트웨이 토큰").
- 맥락: `X-Openit-User`는 platform 공개 입구가 사람 인증을 마친 뒤 붙인다. 다른 토큰(수집, 이웃 읽기, 그 밖의 검토 토큰)을 가진 호출자가 같은 헤더를 보내 신원을 만들 수 있었다.
- 결정: 게이트웨이 토큰 = `deploy-exposure.json`의 `upstream_token`(`ops-read-reviewer`, `ops-review-reviewer`)이 가리키는 토큰 = 이 서비스 설정에서 역할 이름 `reviewer`의 읽기·검토 토큰(`link_ingest_api.GATEWAY_ROLES`). 그 요청에서만 헤더를 신원으로 쓰고, 그 밖의 토큰의 헤더는 무시한다. 신원이 필수인 검토 면(`OPS_REVIEW_REQUIRE_USER`, 기본 켬)에서는 무시된 헤더가 신원 없음이므로 401이다. 새 환경 변수 없음.
- 왜: OWASP ASVS 4.1.3 신뢰 경계. 계약이 정한 규칙이다.
- 검토한 대안: 역할 이름 `gateway`(3.4.4)는 서비스마다 토큰 파일 구성이 달라 맞지 않았다(계약 정정). 토큰 값 목록을 따로 설정: 새 이름이 필요해 버렸다.
- 결과: 얻는 것은 위조 신원 차단. 감수하는 것: 역할 이름 `reviewer`가 곧 게이트웨이 토큰이라는 약속(시험이 deploy-exposure.json 과의 일치를 본다).
- 되돌리는 조건: 계약이 게이트웨이 토큰을 다른 방식으로 정하면.
