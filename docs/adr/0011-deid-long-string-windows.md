# 0011. 비식별 결과의 긴 문자열은 거부하지 않고 창으로 검사한다

- 상태: 채택. 이전의 "4,096자 초과면 DeidError"(round2 M2)를 대체한다(Supersedes: CHANGELOG의 round2 M2 항목, 상수 `MAX_LEAF_CHARS`).
- 맥락: 잔존 패턴은 설정의 정규식이라 입력 길이에 선형이라는 보장이 없다. 그래서 긴 문자열에 정규식을 돌리지 않고 닫았다. 그런데 문진 스키마(`TurnTrace.json`)의 문자열에는 `maxLength`가 없다(읽어서 확인: 파일에 maxLength 0건). 설정이 `scrub_string_keys`로 발화 같은 자유 문장을 남기거나 값 검증 없는 keep 키를 두면, 정상 trace가 4,096자를 넘어 DEID_FAILED가 될 수 있다. 4,096은 근거 없는 임의값이었다.
- 결정: 문자열을 4,096자 창(겹침 1,024)으로 나눠 각 창에 잔존 패턴을 돌린다. 길이 때문에 거부하지 않는다.
- 왜: 목적은 한 번에 정규식이 보는 길이를 묶는 것이지 정상 데이터를 거부하는 것이 아니다. 창 안에서는 이전과 같은 시간 한도가 유지된다. 겹침 1,024는 예시 설정의 잔존 패턴이 낼 수 있는 가장 긴 일치(이메일 약 64+1+255+1+TLD, 전화·주민번호는 수십 자)보다 크다. 창·겹침 값은 측정하지 않았다.
- 대안: 상한을 8 MiB(수집 본문 상한)로 올림 -> 선형이 아닌 정규식에 대한 보호가 사라진다. 계속 거부 -> 정상 trace를 닫고 재처리해도 같은 결과라 원본이 보존 기한에 지워진다. 스키마에 상한을 요청 -> 그것은 survey-service 몫이며, 이 영역은 상한이 없어도 안전해야 한다.
- 결과: 얻는 것은 정상 긴 trace의 처리와 창당 시간 한도. 감수하는 것은 1,024자보다 긴 일치를 내는 사용자 정의 패턴이 창 경계에서 놓칠 수 있다는 점(그런 패턴을 쓰려면 겹침을 키운다). 전체 비용은 문자열 길이에 선형이다.
- 되돌리는 조건: 문진 스키마가 문자열 최대 길이를 정하면 그 값에 맞춰 다시 정한다.
