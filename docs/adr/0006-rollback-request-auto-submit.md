# 0006. 롤백은 요청만 만들고 auto_submit은 기본 false

- 상태: 채택(브리프 6절, D88/U11).
- 맥락: 실패율이 기준을 넘으면 되돌려야 하지만 활성 포인터는 게이트만 바꾼다. Trace는 수집 토큰만 있으면 위조할 수 있다(CR-006).
- 결정: `RollbackPlanner`가 `RollbackRequest`를 만들어 저장하고, `auto_submit: true`일 때만 게이트(I5)로 전달한다. `auto_submit`은 YAML 불리언만 받는다(문자열 "false"는 시작 거부). 요청 id는 (현재 릴리스, 되돌릴 릴리스, 포인터 버전)의 해시라 재실행·동시 실행이 같은 요청을 가리킨다. 기준(window_hours, min_turns, max_failure_rate 등)은 코드에 값이 없고 설정에만 있다.
- 왜: 환자 안전에 닿는 자동 조치는 사람 승인을 기본으로 한다는 D88/U11. 멱등 id는 FAULT_POLICY 원칙 2·12(재전송 안전). 기준 값은 사용자 결정(코드 기본값 없음).
- 대안: 항상 자동 전달 -> 위조 Trace(CR-006)로 롤백이 유발될 수 있다. 롤백을 직접 수행 -> 브리프 6절이 금지.
- 결과: 얻는 것은 안전한 기본. 감수하는 것은 사람 개입 지연. 게이트가 request_id를 멱등으로 받는지는 확인 못 함.
- 되돌리는 조건: CR-006의 출처 인증·서명이 생기고 사용자가 기준을 정하면 자동 전달을 켤 수 있다.
