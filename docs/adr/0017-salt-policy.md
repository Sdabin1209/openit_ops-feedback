# 0017. 의사 식별자 salt 정책: 32바이트 이상, 비밀 파일, 기동 때 길이 검사, 회전은 재가명화 절차

- 상태: 채택(헤드 결정, 표준성 점검 2026-10-29 B6 = `docs/audit/standards-2026-10-29.md`). 원문 대조: 아래 표준 이름과 요구는 원문을 다시 열어 확인하지 않았다.
- 맥락: salt(HMAC 키, ADR 0016)는 전역 하나이고 길이·생성 방법 요구가 없었다. 비어 있지만 않으면 `"x"` 한 글자도 통과했다. 회전 절차와 분리 보관 문서도 없었다.
- 결정:
  1. **길이**: salt는 UTF-8 바이트 32 이상이어야 한다(`deid.MIN_SALT_BYTES`). 잡(`build_from_config`)과 `admin delete-session`이 시작 때 검사하고, 모자라면 값을 싣지 않은 오류로 거부한다(잡은 저장소를 열기 전, admin은 종료 코드 2). 한 글자 단위가 아니라 바이트 단위로 센다.
  2. **생성**: 배포마다 CSPRNG로 만든 32바이트 이상 무작위 값을 비밀 파일(`OPS_DEID_SALT_FILE`, D84)로 둔다. 예: `head -c 32 /dev/urandom | base64 > salt`(44자, 파일 권한은 배포가 정한다). **코드는 CSPRNG로 만들었는지 알 수 없으므로 길이만 검사한다.** 사람이 정한 문구를 32자 이상으로 늘려도 통과한다.
  3. **보관**: 가명처리의 관행은 추가정보(여기서는 salt)를 가명 데이터와 분리해 보관하는 것이다(개인정보 보호법 가명정보 규정과의 관계는 확인 못 함, 감사 보고서 B12). salt는 이미지·리포지토리·설정·로그에 두지 않고(기존 D84 규칙), 사례 DB와 같은 접근 범위에 두지 않는다. 이 접근 범위 분리는 deploy가 정한다. 이 영역은 확인하지 못했다.
  4. **회전**: 자동 회전은 하지 않는다. 회전은 "재가명화 절차"로 사람이 수행한다. 코드와 문서에서 읽어서 안 사실(시험하지 않음): salt가 바뀌면 `p-…`와 그에서 파생한 `case_id`·trace ref가 모두 달라진다(runbook 59행). 원본은 `raw_days`(기본 30일) 뒤 지워지므로 그보다 오래된 사례는 새 salt로 다시 만들 수 없다. `admin delete-session`은 salt 하나만 받으므로 **옛 salt로 가명화된 데이터를 지우려면 옛 salt가 필요**하다. 따라서 절차(제안): (a) 새 salt를 만든다. (b) 옛 salt를 `cases_days`(기본 180일) 동안 보관한다. 그동안의 삭제 요청은 옛 salt로 `delete-session`을 한 번 더 돌린다. (c) 원본이 남은 구간을 새 salt로 다시 만들려면 `job --reprocess`로 처리 표시를 지우고 다시 돌린다(같은 입력은 새 case_id를 내므로 옛 사례와 중복되어 보인다, 사례 정리 방법은 미정). 이 절차의 단계별 시험은 하지 않았다.
- 왜: 키 있는 해시의 키는 추측되지 않아야 한다. 짧거나 사람이 고른 값은 사전 대입에 약하다. 32바이트 하한은 HMAC-SHA256의 출력 길이와 같게 잡았고 RFC 2104가 키를 해시 출력 길이 이상으로 권한다고 알고 있다(원문 대조 전). 이 값은 표준 문서에서 확인한 숫자가 아니라 그 이해에 근거한 하한이고, 측정하지 않았다.
- 대안: (a) 길이 검사 없음: 한 글자 salt를 허용한다. (b) 엔트로피 추정 검사(문자 종류 등): 사람이 쓴 긴 문구와 무작위 값을 구별하지 못하는 휴리스틱이라 하지 않았다. (c) 영역이 salt를 직접 생성: 배포가 비밀 생성을 맡는 D84와 어긋나고, 이 영역이 비밀을 만들어 보관하게 된다. (d) 자동 회전: 원본 보존이 짧아 옛 사례를 다시 만들 수 없어 연결이 끊긴다.
- 결과: 얻는 것은 기동 때 약한 salt의 거부. 감수하는 것은 기존에 짧은 salt로 운영 중인 배포가 업그레이드 뒤 시작하지 못한다는 점(새 salt가 필요하고 위 회전 절차를 따른다). 기존 배포 유무는 확인하지 못했다. 시험·스모크의 salt는 32바이트 이상으로 바꿨다. `Deidentifier` 생성자는 비어 있지 않은지만 검사한다(단위 시험이 짧은 salt를 쓴다). 길이 정책은 기동 경로(`build_from_config`, admin)에 있다.
- 되돌리는 조건: 계약이나 보안 요구가 다른 길이를 정하면 `MIN_SALT_BYTES`만 바꾸고 이 ADR을 새 ADR로 대체한다. 표준 대조에서 위 이해가 틀렸다면 마찬가지.
