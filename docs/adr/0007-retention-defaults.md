# 0007. 보존 기본값(D88/U4)

- 상태: 채택, 잠정 기본값(병원 규정이 다르면 설정만 바꾼다).
- 맥락: 점검(C3, H)에서 원본이 기본 무기한 보관되고 사례 저장소에 삭제 경로가 없었다.
- 결정: `retention.raw_days` 30(처리 끝난 원본), `cases_days` 180(비식별 사례·고아 trace), `metrics_days` 365(지표·롤백 기록). 키를 생략하면 이 값, `null`·0·문자열은 시작 거부, 무기한은 명시적 `"forever"`(경고). 처리 표시가 없는 원본은 지우지 않고 기한을 넘기면 경보한다. 즉시 줄이려면 `raw_after_processing: minimize`. 세션 단위 삭제와 수동 정리는 `python -m ops_feedback.admin`.
- 왜: 값은 D88/U4가 정했다(최소 보존: 원본 30일, 사례 180일, 기록 1년). 이 영역이 독자적으로 근거를 만든 값이 아니다. 개인정보 최소 보존·보관 기한 설정이라는 일반 원칙을 따른다. "미처리 원본 미삭제"는 잡이 기한보다 오래 멈춰도 처리 전에 데이터를 잃지 않기 위함(이 영역의 판단).
- `failed_raw_days` 90: D88에 없는 값이다. raw_days의 3배로 둔 **근거 기록 없는 임의값**이고 사용자 결정 대상이다. 재시도 대상 원본을 일반 기한에 지우면 재처리 기회를 잃기 때문에 별도 기한을 둔다.
- 대안: 기본 무기한 유지 -> 점검 H 문제. 처리 직후 삭제 -> 중복 수집(재전송)이 다시 ACCEPTED로 들어와 중복 판별이 깨진다. 그래서 `minimize`는 봉투 내용만 지우고 (session_id, turn_id)·해시는 남긴다.
- 결과: 얻는 것은 유한 보존. 감수하는 것은 확정(CONFIRMED) 사례도 180일 뒤 지워진다는 것(`cases_purge_confirmed: false`로 보호 가능), 사례 삭제 뒤 학습 시드를 쓰려면 그 전에 소비해야 한다는 것.
- 되돌리는 조건: 병원 규정이 다른 기간을 요구하면 설정만 바꾼다. 백업(deploy)의 보존과 정렬은 deploy 몫(14일 일일 백업, D88/U4)이며 확인하지 못했다.
